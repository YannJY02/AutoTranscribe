# Preserve audio/video sync through recording pause

Status: ready-for-human

## Parent

- `.scratch/live-workspace-session/PRD.md`

## Triage Notes

> *This was generated by AI during triage.*

**Category:** bug

**Summary:** The new Live Workspace pause/resume control can make saved review video feel out of sync again.

**Current behavior:**
After issue 05, `暂停` no longer stops the recording. It pauses audio sample ingestion and video writer appends. However, the shared capture timeline used by review-media composition only stores the original video and audio start anchors. It does not store pause intervals, so a pause that occurs before the first audio sample, or between source start anchors, can make the final composer select the wrong video source window.

**Desired behavior:**
Pause/resume should be part of the canonical capture timeline. Saved review media must align audio and video by active recording time, excluding paused wall-clock time. The final `capture_timeline.json` should preserve enough pause metadata for diagnostics to catch this class of regression.

**Key interfaces:**
- `LiveMediaCaptureTimeline` should convert wall-clock capture anchors into active recording time after subtracting pause intervals.
- `LiveSessionViewModel.pauseLiveSession()` and `resumeLiveSession()` should update the same capture timeline used later by review-media composition.
- `LiveSessionReviewMediaPreparer` should persist pause metadata into `capture_timeline.json`.
- `scripts/diagnose_issue24_media_timeline.py` should report pause intervals so duration-only checks do not hide the bug.

**Acceptance criteria:**
- [x] A regression test proves that a pause before audio starts produces an audio/video composition offset based on active recording time, not raw wall-clock delay.
- [x] Pausing and resuming a live session updates the capture timeline used by `prepareTemporaryRecordingForSave`.
- [x] `capture_timeline.json` includes pause intervals for new composed review media.
- [x] Existing issue 24 media-timeline diagnostics still pass and expose the pause data.
- [x] Full Swift tests pass before commit.

**Out of scope:**
- Changing the accepted camera-overlay saved-output implementation.
- Replacing the AVPlayer review surface.
- Reopening the strict Apple Presenter Overlay feasibility lane.
