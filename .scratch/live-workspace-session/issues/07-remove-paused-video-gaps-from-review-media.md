**Category:** bug

**Summary:** After adding Live Workspace pause/resume, saved review video can run slightly ahead of audio.

**Current behavior:**
The latest manual test Record `20260702-2237-live-record-1335ee42` has final `recording.mp4` audio/video durations of `10.000s`, but its capture source video is `13.503s` while source audio is `10.000s`. The captured pause interval is `2.905s`. Final duration equality therefore hides a source timeline mismatch: pause gaps remain in the video source and the composer only selects one continuous source window.

**Desired behavior:**
Pause should be treated as a gap in the raw video source and removed during final review-media composition. Audio start should be anchored to the first sample in the received audio buffer, not to the later callback receipt time.

**Acceptance criteria:**
- [x] `ReviewMediaCompositionTimeline` carries pause ranges that the composer uses to splice active video segments.
- [x] The final composer skips paused video source ranges instead of inserting one continuous video range.
- [x] The first audio anchor is based on audio buffer start time.
- [x] Issue 24 diagnostics report pause-adjusted source-video duration.
- [x] Focused and full Swift tests pass before commit.
