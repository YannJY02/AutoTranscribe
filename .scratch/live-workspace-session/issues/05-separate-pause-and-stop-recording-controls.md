# Separate pause and stop recording controls

Status: ready-for-human

> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug

**Summary:** Live Workspace pause and stop controls should not both terminate the recording.

**Current behavior:**
The running Live Workspace shows separate `暂停` and `停止录制` controls. The pause action was wired to the same stop/finalization flow as the stop action, so clicking pause ended the recording instead of pausing it. During stop finalization, the controls also remained visually available even though the app was already saving.

Reporter evidence:
- Screenshot: `/Users/yann.jy/Library/Application Support/CleanShot/media/media_6Uaug7HKnx/CleanShot 2026-07-02 at 21.19.13@2x.png`.
- Code verification: `onPauseRecording()` called `stopLiveSession()` in the Live Workspace panel adapter.

**Desired behavior:**
Pause should keep the active Live Workspace session alive and stop writing new audio/video samples until the user continues. Stop should remain the only action that finalizes and saves the Record. While stop finalization is in progress, pause and stop controls should not remain actionable.

**Key interfaces:**
- `CenterStageDataSource` should expose whether recording is paused or finalizing so the UI can show the right label and disable controls at the right time.
- `LiveSessionViewModel` should maintain a pause state separate from running/finalizing state.
- `VideoCaptureService` should pause video writer appends and resume without counting paused wall-clock time in the written video timeline.
- Live audio ingestion should ignore samples while paused without ending the session.

**Acceptance criteria:**
- [x] Clicking `暂停` while recording keeps the session running and does not enter stop/finalization.
- [x] Clicking the same control again resumes recording.
- [x] Paused time is excluded from the video writer presentation timeline after resume.
- [x] Audio samples received while paused are not appended to the live recording pipeline.
- [x] Capture-health warnings do not overwrite the paused recording status while paused.
- [x] `停止录制` remains the action that finalizes and saves the Record.
- [x] Pause and stop controls are disabled while stop finalization is already in progress.
- [x] Focused Swift tests cover pause not stopping the live session and video timeline pause/resume behavior.

**Out of scope:**
- Adding an editing UI for cutting paused sections after recording.
- Reworking Smart Minutes, transcript recovery, or Record Review playback.
- Changing the saved-output camera overlay implementation beyond preserving pause/resume timing.
